Cybersoul：产品简报

本文介绍 Cybersoul 的产品对象、当前 CyberWorld demo 的运行逻辑、已经落地的系统链路，以及这一阶段能够验证的核心技术判断。

March 13, 2026

Project Article

Cybersoul 将陪伴 AI 定义为持续运行的数字生命系统，而不是一次一答的聊天界面。当前仓库对应的是一个可观察、可调试、可积累记忆的 CyberWorld runtime demo。

当前对象
一个围绕 Mira 展开的 CyberWorld 运行时 demo，而不是完整产品外壳。
核心问题
验证陪伴体能否在时间推进、状态漂移和记忆积累中保持连续存在。
可观察面
世界状态、情绪变化、生活时间线、日志链路和控制面板已经打通。

1. 主题

Cybersoul 面向长期陪伴场景。它不把陪伴体理解为聊天窗口里的回复器，而把它定义为一个在内部世界中持续生活、不断更新状态、逐步形成记忆痕迹的数字存在体。本文讨论的对象不是最终版产品，而是这套定义在当前阶段的最小可运行形态。

这个最小形态就是 CyberWorld demo。它将世界、角色、时间、事件和仪表盘聚合到一个受控沙盒中，使“陪伴体是否真的在生活”可以被观察，而不是只靠一轮对话的主观印象来判断。

2. 原理

Cybersoul 的产品逻辑建立在两个空间上。第一个空间是内部的 CyberWorld，它提供地点、时间、事件、节律和生活上下文。第二个空间是真实互联网，它将来负责接住更开放的连接和行动。当前阶段只聚焦第一个空间，因为项目首先要证明的是“持续存在”而不是“互联网功能覆盖”。

这一定义对应三个关键判断。第一，陪伴体验的基础不是单次输出质量，而是连续生活感。第二，连续生活感来自状态更新、世界反馈和记忆累积，而不是孤立 prompt。第三，可观察性必须与生命感同步建设，否则系统很难调试，也很难判断什么行为是真正由世界驱动产生的。

当前阶段的边界

这个 demo 还没有接入真实互联网，也没有把用户直接放进 CyberWorld 内部进行沉浸式互动。它证明的是运行时骨架，而不是最终版陪伴产品的全部界面能力。

3. 实现

当前实现被收敛为 `city_loop_v1`。世界层由 YAML 配置驱动，包含 5 个地点、10 个活动、12 类世界事件与对应节律窗口。运行时按分钟推进模拟时间，并在每次 tick 中完成世界效果应用、事件检查、信号评估和角色状态更新。

陪伴体层围绕 Mira 展开。她不是单次响应函数，而是一个会在公寓、图书馆、咖啡馆、通勤路和河边公园之间切换活动的运行时角色。世界侧还定义了其他角色，用来提供环境反馈和互动信号，从而避免陪伴体只面对静态背景。

系统层已经具备 SQLite demo store、内部 message bus、FastAPI dashboard API、日志回写和记忆链路。控制面板能够把运行时拆成状态总览、情绪变化、世界动态、时间线和 LLM 日志几个观察窗口，便于把系统当作一个活的 runtime 调试。

世界层

地点、活动、事件和节律先定义好最小生活回路，再通过 minute tick 持续推进。

陪伴体层

Mira 根据世界信号、内部状态和记忆链路判断下一步行动，而不是只对输入文本做即时反应。

观察层

仪表盘、日志和 store 让每次状态变化都可以被回放、检查和继续迭代。

4. Demo 结果

当前 demo 已经能够以一个明确的清晨状态启动，并通过控制面板手动推进世界。每一次 tick 都会带来可见的状态变化，包括地点切换、活动更新、情绪波动、事件触发和日志记录。系统输出的对象不再只是文本，而是一个持续演化的生活切片。

更重要的是，这条链路已经可以暴露出运行时设计中的真实问题。例如某些行为是否被世界条件触发，某些记忆是否应当被保留，某些状态迁移是否足够平滑，都能在仪表盘上被直接验证。这个阶段因此具有很强的工程价值，而不只是概念展示价值。

状态轨迹

地点、活动、精力和情绪会沿时间线持续变化，形成可回看的一天。

事件驱动

世界事件和节律窗口共同决定角色是否切换活动，而不是把行为完全交给单轮生成。

记忆回写

日志和 memory writeback 让 demo 具备生活痕迹，而不是每轮结束后完全重置。

5. 结论

Cybersoul 当前阶段已经证明，一个陪伴 AI 的核心技术对象可以从“对话接口”转成“持续运行的世界化存在”。对这个项目而言，先做小而完整的 CyberWorld 是正确路线，因为只有先跑通时间、世界、角色、记忆和观察闭环，后续的互联网接入和产品外层设计才有稳定底座。

因此，这个 demo 的贡献不是功能数量，而是对象定义的落地。它把长期陪伴从一个模糊体验词，压缩成了一个可以被调试、比较和继续扩展的运行时问题。
